# 07. UI/UX

원칙: **심플·모던, 모바일 퍼스트, 다크모드 지원**. 화면 수를 최소화하고 밀도를 낮게 유지한다.

## 디자인 시스템

- **Tailwind CSS v4** (CSS-first 설정, `@theme`). 별도 tailwind.config 불필요한 v4 방식 사용.
- 컴포넌트: shadcn/ui 스타일(Radix 기반)을 **필요한 것만 복사** — dialog, dropdown-menu, button, input, select, badge. 전체 킷 설치 금지.
- 아이콘: `lucide-react`. 토스트: `sonner`.
- 색: 뉴트럴(zinc) 스케일 + 액센트 1색(blue 계열). 카테고리 색은 8색 프리셋 팔레트(red/orange/amber/green/teal/blue/violet/pink)의 **키를 DB에 저장**하고(`categories.color`) CSS에서 매핑 — hex를 저장하지 않는다.
- 다크모드: `prefers-color-scheme` 기본 + 수동 토글(설정, localStorage 저장, `<html>` class 방식).
- 타이포: 시스템 폰트 스택 (`font-sans` 기본). 웹폰트 로딩 없음 (성능).
- 라운드/그림자: `rounded-xl`, 그림자 대신 `border` 위주 — 플랫하고 정돈된 인상.

## 라우트 구조 (TanStack Router 파일 기반)

```
src/routes/
├── __root.tsx          # html shell, QueryClientProvider, Toaster, 테마
├── login.tsx           # 로그인 (비인증 유일 화면)
└── _authed/            # beforeLoad에서 세션 가드 (04-auth)
    ├── route.tsx       # 레이아웃: 콘텐츠 + 하단 탭(모바일) / 상단 헤더(데스크톱)
    ├── index.tsx       # 홈: 북마크 목록
    ├── map.tsx         # 지도(게시물별 마커 그룹)
    ├── reminders.tsx   # 리마인더 목록
    └── settings.tsx    # 설정
```

네비게이션: 모바일은 상단 헤더 없이 하단 바 5개(라이브러리 / 지도 / 리마인더 / 추가 / 설정)만 사용하고, `sm:` 이상은 브랜드와 햄버거 메뉴가 있는 상단 헤더로 전환한다. 햄버거에는 라이브러리 / 지도 / 리마인더 / 설정 / 로그아웃을 넣는다. 모바일 `추가`는 어느 탭에서 눌러도 라이브러리로 이동해 추가 bottom sheet를 연다.

## 화면 명세

### 홈 (`/`)

```
┌────────────────────────────────┐
│ [🔍 검색________________]      │  ← 입력 300ms debounce → q 파라미터
│ (전체) (미분류) (개발) (디자인)…  │  ← 카테고리 칩, 가로 스크롤, count 표시
├────────────────────────────────┤
│ ▢ favicon  제목                 │  ← BookmarkCard
│   domain · 카테고리배지 · 2일 전 │
│   [분석중…]                     │  ← ai_status=pending일 때 배지
│ ▢ …                            │
└────────────────────────────────┘
│                           (＋) │  ← 데스크톱 우측 하단 floating action
│  ▣ 라이브러리  ⏰ 리마인더  ＋ 추가  ⚙ 설정 │  ← 하단 바 (모바일)
```

- 카드 탭 → 원본 URL 새 탭 열기. 카드의 `⋯` 메뉴 → 리마인더 설정 / 편집 / 삭제 / (failed일 때) AI 재분류. 메뉴는 외부 클릭, Escape, 액션 선택 시 닫힌다. 카테고리 변경은 편집 폼에서 수행한다.
- 북마크 카드와 이미지 상세는 메타데이터 아래에 장소 칩 목록을 표시한다(`-components/bookmark-places.tsx`). 칩은 `MapPin` 아이콘 + 이름 링크이며 `mapUrl`을 새 탭으로 연다(국내는 네이버지도, 해외는 구글맵). 카드는 최대 3개까지 보이고 나머지는 `+N` 버튼으로 접어 누르면 펼치며, 상세는 전부 보인다. 칩 hover는 URL 메타데이터 뱃지와 같은 파란 계열이다(2026-07-15 통일 결정 유지).
- 카드 태그는 모바일에서 11px 읽기 전용 뱃지로 표시하고, `sm:` 이상에서는 같은 크기의 태그 검색 버튼으로 전환한다.
- 이미지 상세는 썸네일을 먼저 표시하고 명시적 `원본 보기`에서만 원본·다운로드를 노출한다. 정보 영역에는 파일명·해상도·용량·분석 상태 대신 등록일만 표시한다. `네이버지도` 메타데이터 링크는 호버 시 네이버 녹색 배경과 흰 글자로 전환한다.
- 무한 스크롤: `useInfiniteQuery` + cursor. 100개 이상 렌더 시 TanStack Virtual 적용 (08-performance).
- `ai_status=pending` 항목이 있는 동안만 5초 간격 refetch로 분류 완료를 반영 (폴링은 pending 존재 시에만).
- 빈 상태: "첫 북마크를 추가해보세요" + 추가 버튼.

### 추가 다이얼로그 (데스크톱 우측 하단 floating [＋] / 모바일 하단 바 [추가], 모바일에선 bottom sheet 스타일)

추가·편집 surface는 콘텐츠 가독성을 위해 blur 없는 불투명 배경을 사용하고, 바깥 scrim에만 3px의 약한 backdrop blur를 적용한다. scrim 자체를 클릭하면 모달을 닫되 surface 내부 클릭은 닫힘으로 처리하지 않는다.

```
URL   [https://…________________]
분류   (● AI 자동)( 직접 선택 )( 미지정 )   ← 3-토글, 기본값: AI 자동
       └ "직접 선택" 시 카테고리 select 노출 (+ 새 카테고리 인라인 생성)
                              [저장]
```

- 저장 → optimistic하게 목록 반영, 409(중복)면 "이미 저장된 링크예요" 토스트 + 해당 카드로 스크롤.
- 마지막 선택 모드를 localStorage에 기억.

### 지도 (`/map`)

`apps/web/src/routes/_authed/map.tsx`. 데스크톱 헤더 메뉴와 모바일 하단 바에 "지도" 항목이 있다. 데이터는 `GET /api/places`(`['places']`)이며 북마크 생성·수정·삭제·재분류 mutation 성공 시 `['bookmarks']`와 함께 invalidate한다.

- **SDK**: 네이버 지도 JavaScript API v3(`https://oapi.map.naver.com/openapi/v3/maps.js?ncpKeyId=…`, 현행 파라미터 이름은 `ncpKeyId`)를 `/map` 진입 시에만 스크립트 삽입으로 로드한다(`/map` 청크에만 코드가 있음). 타입은 `@types/navermaps`(devDependency). SDK는 `lib/map-adapter.ts`의 얇은 어댑터 뒤에 있고 테스트에서는 fake로 대체한다. `VITE_NAVER_MAP_CLIENT_ID`가 없거나 SDK 로드·인증(`navermap_authFailure`)에 실패하면 지도 위에 안내 문구를 덮고 목록은 그대로 동작한다.
- **마커 그룹 = 게시물**: 같은 북마크의 마커는 같은 색(고정 10색 팔레트를 전체 목록 순서로 순환, 검색 전후로 불변)이며 HTML 마커(색 원 + 게시물 안의 순번)로 그린다. 처음에는 전체 마커가 보이도록 `fitBounds`하고, 게시물을 선택하면 그 그룹만 강조하고 나머지는 반투명으로 낮춘 뒤 그룹 마커 전체로 `fitBounds`한다. 선택 해제(지도 빈 곳 클릭·닫기)하면 전체 보기로 돌아간다. 마커 클릭도 같은 선택이다.
- **패널**(데스크톱 좌측 사이드, 모바일은 지도 아래 시트): 선택이 없으면 게시물 그룹 목록(제목 + 장소 수), 선택하면 게시물 제목(링크는 원문, 이미지는 `/images/:id`)과 장소 행. 장소 행을 누르면 해당 마커로 이동하고 "네이버지도" 버튼이 네이버지도를 연다.
- **지도 컨트롤**: 지도 옵션은 `zoomControl: false`, `scaleControl: false`다(기본 줌 UI와 우하단 축척 바 제거). 네이버 로고·저작권(`logoControl`, `mapDataControl`)은 약관상 기본값(표시)을 유지한다. 줌은 지도 영역 우하단(로고·저작권 위로 띄움)의 자체 +/− 버튼(`.map-zoom-group`/`.map-zoom-button`, `Plus`/`Minus`, `aria-label` "확대"/"축소", 세로로 붙은 둥근 surface 그룹, 라이트·다크 대응, 키보드 포커스 링)이 맡는다. 클릭은 어댑터의 `zoomIn()`/`zoomOut()`(현재 줌 ±1, 애니메이션 `setZoom(…, true)`)을 호출하고, 어댑터의 `subscribeZoom`(`zoom_changed` 이벤트 + 최초 1회 즉시 호출)이 최소·최대 줌에서 해당 버튼을 `disabled`로 동기화한다. 지도가 없을 때(키 미설정·SDK 로드/인증 실패) 버튼은 숨긴다. 핀치·스크롤 줌은 SDK 기본 동작 그대로다.
- **호버 강조**(선택이 없을 때의 그룹 목록): 그룹 행에 마우스를 올리거나 키보드 포커스가 가면 선택과 같은 시각 규칙(그 그룹 `active`, 나머지 `dim`)을 지도에 미리 보여 준다. 지도는 움직이지 않으며(`fitBounds` 없음) 벗어나면 이전 상태로 돌아간다. 선택이 있으면 선택이 우선하고, 장소 행에 호버·포커스하면 그 장소 마커 하나만 더 크게(`scale 1.6`)·앞으로(`zIndex 2000`) 강조한다. 터치 포인터는 무시한다(pointer 이벤트의 `pointerType === "touch"`). 선택이 바뀌면 호버 상태를 비운다.
- **지도 표시/숨김**: 그룹 행 오른쪽의 눈 아이콘(`Eye`/`EyeOff`) 토글이 게시물 단위로 마커를 숨기거나 보인다(`aria-label` "지도에서 숨기기"/"지도에 표시", `aria-pressed`는 "숨김 상태"). 숨긴 그룹은 마커와 전체 보기 `fitBounds` 계산에서 빠지고, 목록에는 흐리게 남아 다시 켤 수 있다. 숨긴 그룹 또는 개별 숨김 장소가 결과에 하나 이상이면 목록 상단에 "숨긴 n개 모두 표시"가 나타나며, n은 현재 검색 결과 안의 숨긴 그룹 수 + 그 그룹들에 속한 개별 숨김 장소 수이고 누르면 둘 다 해제한다. 숨긴 그룹을 선택하면 자동으로 다시 표시한다. 그룹 색은 숨김과 무관하게 전체 목록 기준이다. 그룹 숨김 상태는 기기별 설정으로 `localStorage`(`my-bookmark:map-hidden-groups`, 북마크 id의 JSON 배열)에 저장하며 읽기·쓰기 실패는 무시한다(`lib/map-visibility.ts`). 마커·보기 좌표 계산은 순수 함수(`lib/map-view.ts`)다.
- **개별 장소 숨김**: 게시물을 선택하면 펼쳐지는 장소 행마다 눈 토글(`Eye`/`EyeOff`, `aria-label` "이 장소 지도에서 숨기기"/"이 장소 지도에 표시", `aria-pressed`는 "숨김 상태")이 있어 핀 하나씩 끄고 켠다. 숨긴 장소는 마커와 `fitBounds` 계산에서 빠지고(선택된 그룹 안에서도 동일) 장소 행은 흐리게 남으며, 남은 핀의 순번 라벨은 그대로다. **그룹 숨김이 우선**이다: 그룹을 숨기면 개별 상태와 무관하게 그 그룹의 핀이 모두 숨고, 다시 표시하면 개별 숨김은 그대로 유지된다. 그룹 행의 "장소 n곳" 옆에 개별 숨김이 있으면 "(m곳 숨김)"을 덧붙인다. 보이는 핀이 하나도 없는 그룹의 호버 강조는 다른 그룹을 흐리게 하지 않는다. 상태는 그룹 숨김과 별도 키 `my-bookmark:map-hidden-places`(장소 id의 JSON 배열, 기존 키와 하위 호환)에 저장하며 읽기·쓰기 실패는 무시한다. 장소 id가 삭제돼도 무해해 따로 정리하지 않는다. 순수 계산은 `lib/map-view.ts`(`hiddenPlaceIds`)에 있다.
- **검색**: 패널 상단 입력 하나로 게시글(제목)·장소(이름)·지역(`locality`, 주소)을 검색한다. `/api/places` 응답을 클라이언트에서 필터링하며(`lib/place-search.ts`), 대소문자·공백을 무시한 부분 일치이고 공백으로 나뉜 여러 단어는 모두 일치해야 한다(AND). 제목만으로 모든 단어가 일치하면 그 게시물의 장소 전부를 남기고, 아니면 장소(이름·지역·주소 + 소속 제목)마다 판정해 일치한 장소만 남기며 장소가 남지 않은 게시물은 뺀다. 결과 마커와 목록이 함께 좁혀지고 결과 마커 전체로 `fitBounds`한다. 걸린 장소는 목록에 이름·지역으로 표시하고 결과가 없으면 "검색 결과가 없습니다"를 보여 준다. 검색어는 URL `q`에 200ms 디바운스로 반영한다(`/map?q=서촌`). 선택된 게시물이 결과에서 빠지면 선택을 해제한다.
- `/map?bookmark=<id>`로 진입하면 그 게시물을 선택한 상태로 연다. 검색 파라미터(`q`, `bookmark`)는 zod로 검증하며 잘못된 값은 무시한다. 카드·이미지 상세의 장소 칩 옆 "지도에서 보기" 링크가 이 URL로 이동한다(좌표가 있는 장소가 하나라도 있을 때만).
- **네이버지도 열기**(`lib/naver-map-link.ts`): 모바일(iOS/Android UA) + 좌표가 있으면 `nmap://place?lat=&lng=&name=&appname={location.host}`로 이동을 시도하고 1.5초 뒤에도 문서가 보이면(`visibilityState === 'visible'`) `mapUrl`을 연다. 그 외에는 `mapUrl`을 새 탭으로 연다.
- 빈 상태: 좌표가 있는 장소가 없으면 "지도에 표시할 장소가 없습니다".
- **서비스 워커**: `/api/places`는 기존 API 캐시 정책상 network-only(서명된 썸네일·사용자 데이터)다. 네이버 지도 SDK·타일 요청(`*.naver.com`, `*.naver.net`, `*.pstatic.net`)은 서비스 워커가 가로채지 않는다(`shouldHandleFetch`). 네이버 클라우드 플랫폼 콘솔의 Web 서비스 URL에 배포 도메인(개발 시 `http://localhost`)을 등록해야 인증이 통과한다.

### 리마인더 (`/reminders`)

- pending 리마인더 목록 (시간순): 북마크 제목 + remind_at + note, 액션: 시간 변경 / 취소.
- 생성 진입점은 북마크 카드 메뉴의 "리마인더 설정" → 날짜/시간 피커 다이얼로그 (`datetime-local` 입력이면 충분).
- 알림이 꺼져 있으면 상단에 "푸시 알림이 꺼져 있어요 → 설정에서 켜기" 배너.

### 설정 (`/settings`)

섹션 순서:
1. **알림** — 푸시 켜기/끄기 토글, "테스트 알림 보내기" 버튼, iOS 미설치 시 안내문구 (06-pwa-push)
2. **카테고리 관리** — 목록(이름/색/개수), 추가·이름변경·색변경·삭제(확인 다이얼로그: "북마크 N개가 미분류가 됩니다")
3. **API 키** — 발급(이름 입력 → 키 1회 표시 + 복사 버튼 + "다시 볼 수 없어요" 경고), 목록(prefix, 마지막 사용), 회수. 하단에 단축어 설정 가이드 링크
4. **AI** — provider별 독립 API 키 카드(입력/교체/연결 테스트/삭제)와 별도 사용 모델 선택 영역. 모델 목록에는 키가 등록된 provider의 저비용/균형 모델만 표시하고, 키가 0개면 등록 안내 빈 상태 표시. 저장된 키 원문은 다시 표시하지 않음
5. **테마** — 시스템/라이트/다크
6. **계정** — 이메일 표시, 로그아웃

모바일 카테고리 행은 드래그 핸들이 왼쪽 두 행을 차지하고, 오른쪽에 이름 입력과 개수·삭제 액션을 두 줄로 배치한다. `sm:` 이상에서는 핸들·이름·개수·삭제를 한 줄로 표시한다. DND 센서와 저장 방식은 viewport와 무관하게 동일하다.

### 로그인 (`/login`)

중앙 카드 1개: 이메일/비밀번호/로그인 버튼. 실패 시 "이메일 또는 비밀번호가 올바르지 않습니다" (구체 사유 노출 금지). 가입/비밀번호 찾기 링크 없음 — 1인 서비스.

## 상태 관리 규칙

- 서버 상태는 전부 TanStack Query. 전역 클라이언트 상태 라이브러리(zustand 등) 도입 금지 — 테마/모드 기억 정도는 localStorage + React state로 충분.
- Query key: `['bookmarks', { categoryId, q }]`(infinite), `['categories']`, `['reminders']`, `['apiKeys']`, `['places']`.
- API 호출 전 access token이 없거나 401 뒤 refresh가 실패하거나 재시도도 401이면 현재 내부 경로를 보존해 `/login`으로 이동한다. 5xx·네트워크 실패·JWKS 502는 세션 만료로 취급하지 않는다.
- mutation 후 관련 key invalidate. 북마크 추가/삭제는 optimistic update 적용, 나머지는 invalidate만으로 충분.
- 폼: 추가 다이얼로그와 로그인은 TanStack Form + zod validator (`packages/shared` 스키마 재사용).

## 접근성/품질 기준

- 터치 타깃 최소 44px, 포커스 링 유지(Radix 기본), `aria-label` 필수인 아이콘 버튼.
- 모든 인터랙션에 로딩/에러 피드백 (버튼 spinner, sonner 토스트).
- 반응형 기준: 기본 = 모바일(~640px), `sm:` 이상 데스크톱 — 브레이크포인트 2단계만 사용.
